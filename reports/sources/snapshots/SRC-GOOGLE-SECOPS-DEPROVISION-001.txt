Deprovision

This document explains how to use the self-service deprovisioning feature in Google Security Operations to delete a Google SecOps tenant and all related data.

With deprovisioning, you can remove user access to Google SecOps and delete the tenant, including all associated data and resources.

Billing implications of deleting your instance
Deleting a Google SecOps instance does not cancel your billing.
If you have an active contract, you're still responsible for the full contract value, even after you delete the instance.
Billing continues until the contract term ends, regardless of the tenant's status.

Deprovisioning phases
Self-service deletion occurs in two phases:
Soft delete phase (12-day grace period)
Hard delete phase (permanent deletion)

During the soft delete phase, the system disables UI and API access and data ingestion is halted. The Data Governor can restore the tenant within 12 days.

Projects where customers directly manage their own resources and roles aren't deleted. Customers are solely responsible for deleting these projects and any associated data.

After the 12-day soft delete phase has ended, the data deletion process starts. All customer data, including backup snapshots, are permanently deleted. All UI access is permanently deactivated.

Limitations
The deprovision feature only provides self-service capabilities handled by Customer Support. It doesn't unify or automate the deprovision process across all Google SecOps systems.
After restoring a tenant, all data feeds remain inactive. You must manually re-activate the data feeds that you need.
Associated VirusTotal and Mandiant instances require manual deprovisioning.
