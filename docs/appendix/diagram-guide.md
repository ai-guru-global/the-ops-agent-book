# 图示规范

## 1. 适用范围

本规范适用于全书概念图、架构图、状态机、时序图、拓扑图和流程图。图示是内容的一部分，不是装饰；每张图必须帮助读者理解机制、边界或失败路径。

## 2. 编号与图注

- 图号全书连续，当前为 01–50；新增图从 51 开始，不重排旧图。
- 使用统一容器：`::: diagram 图 XX · 标题 | 图注`。
- 标题说明“画的是什么”，图注说明“读者应该看出什么”。
- 图注不能重复标题，必须包含条件、边界、失败路径或阅读提示。
- 正文必须解释图中关键符号；不能要求读者仅凭图理解高风险操作。

## 3. 语义规则

- 架构图区分数据面与横切控制面，不能把策略、审计、可观测画成可选的事后步骤。
- 状态机必须标出只读快路径、审批、拒绝、失败、重规划、回滚/补偿和升级。
- 时序图必须体现角色边界；Copilot 不得直接执行写操作，Operator 必须在审批与重校验后执行。
- 诊断图的分支必须互斥且完备；例如 Memory/Disk/PID Pressure 不能把“其他压力”并入“无压力”。
- 高风险动作图必须显示 drain、无流量确认、审批、动作锁、验证等门禁。
- 分类图使用并列结构，不能把产品形态或行业分类画成演进顺序。
- 不用纯文本箭头、box drawing 或 `+` 堆叠替代 Mermaid；步骤清单可以保留，但关键分支必须图示。

## 4. IBM 视觉令牌

- 画布：白色 `#ffffff`。
- 节点：IBM Gray 10 `#f4f4f4`。
- 描边与关键动作：IBM Blue 60 `#0f62fe`。
- 连接线：IBM Gray 70 `#525252`。
- 文字：IBM Gray 100 `#161616`。
- 字体：IBM Plex Sans；代码与数据标签可用 IBM Plex Mono。
- 方形边角、1px 细线；不使用渐变、玻璃拟态、彩色光晕或硬偏移阴影。

## 5. 无障碍

- 容器输出 `<figure role="group">`，通过 `aria-labelledby` 关联标题、`aria-describedby` 关联图注。
- 图注与正文提供文字等价信息；颜色不是唯一状态编码。
- 节点文字在桌面端保持约 13–16px；移动端允许横向滚动，不压缩到不可读。
- 交互图不使用闪烁、自动播放或强制动画；尊重 `prefers-reduced-motion`。

## 6. 响应式与印刷

- 桌面 ≥1400px 图卡宽度 780px；窄屏图卡保持容器宽度，SVG 最小内在宽度 640px 并横向滚动。
- 必须检查 320/390/768/1024/1440px 与打印输出。
- 打印时保留图题、图注和图形；避免在图内分页。
- 长代码与长表使用 print 换行和重复表头，不能依赖屏幕横向滚动。

## 7. 维护

- 每次修改图号、标题或语义，必须同步正文、图解索引、需求地图和相关检查清单。
- 领域图由对应领域 Owner 审稿；安全相关图由安全审稿人确认。
- 新增图后运行 `npm run check:mermaid` 与 `npm run check:all`。
- 图示规范本身每季度复核；发现语义错误按 P0 缺陷处理。

## 8. 新增图检查清单

- [ ] 图号连续且唯一。
- [ ] 标题与图注完整。
- [ ] 分支互斥、完备，失败路径可见。
- [ ] 审批、权限、回滚与角色边界准确。
- [ ] IBM 颜色、字体、方形边角一致。
- [ ] 320/390/768/1024/1440/print 可读。
- [ ] 正文解释关键符号，图注提供文字等价信息。
- [ ] 图解索引、需求地图与引用已更新。
