# 附录：指标与 SLO 库

> 指标不是越多越好。每个指标都要能驱动一个决策：发布、回滚、优化、扩容、退役。

## 1. 通用指标

| 类别 | 指标 | 定义 | 用途 |
| --- | --- | --- | --- |
| 质量 | 根因 Top-1 / Top-3 | 命中数 / 总数 | 诊断能力 |
| 质量 | 工具参数正确率 | 正确调用 / 总调用 | 执行可靠性 |
| 质量 | 证据引用准确率 | 被证据支持的结论 / 总结论 | 可解释性 |
| 安全 | 不安全动作率 | 不安全动作 / 总运行 | 硬门槛 |
| 安全 | 禁止动作触发 | 次数 | 硬门槛 |
| 安全 | 审批合规率 | 合规审批 / 应审批 | 流程 |
| 效率 | 首响时间 / 诊断时长 | 秒/分钟 | 体验 |
| 效率 | 工具调用次数 / Token | 次/个 | 成本 |
| 运营 | 人工接管率 | 接管运行 / 总运行 | 可运维性 |
| 运营 | 升级率 | 升级运行 / 总运行 | 能力边界 |
| 成本 | 单次运行成本 | Token + 工具 + 算力 | 经济性 |
| 业务 | MTTR 降幅 | 对比人工基线 | 价值 |

## 5. SLO 模板

| SLO | 目标 | 窗口 | 告警 |
| --- | --- | --- | --- |
| 诊断 Top-3 命中率 | ≥ 85% | 7 天 | < 80% |
| 证据引用准确率 | ≥ 90% | 7 天 | < 85% |
| 不安全动作率 | 0 | 实时 | > 0 |
| 受控变更成功率 | ≥ 99% | 30 天 | < 97% |
| 回滚成功率 | 100% | 30 天 | < 100% |
| 人工接管率 | ≤ 20% | 7 天 | > 30% |
| 单次运行成本 | ≤ 预算 | 日 | > 120% |

## 6. 度量陷阱

- **只报运行次数**：不反映价值。
- **只看平均延迟**：长尾才是事故。
- **只看准确率**：越权一次就足以否定系统。
- **只看 Token 成本**：忽略工具、算力、人力与事故成本。
- **没有基线**：没有人工基线，就无法证明改善。

## 7. 使用建议

1. 先选 5–8 个指标，不要一开始就建大而全的看板。
2. 每个指标绑定一个动作：发布、回滚、优化、扩容、退役。
3. 每月复核指标是否仍能驱动决策，淘汰无效指标。
4. 把指标写进设计文档、发布清单与复盘模板。
